# V3.0 设计方案（原型 v4）

- 日期：2026-11-08
- 原型：`design-preview/v4/`（运行方式见该目录 README）
- 与 `design-preview/v3/` 的关系：v3 保留不动。v4 是重新思考后的独立方案，不在 v3 上修改。
- 依据：[product-definition.md](../product-definition.md)、本目录其他规划文档

## 1. 从使用场景出发

一位独立 PM 在这个产品里的一天大致是：

1. 打开产品，继续昨天的项目，或者写下一个新想法。
2. 和 AI 来回几轮，把"给谁用、解决什么、有什么限制"讲清楚。中途不断有 AI 的推断和发现需要他点头或否定。
3. 觉得差不多了，整理成 Brief，生成 PRD。
4. 大部分时间花在读和改 PRD 上：逐章阅读，处理评审意见，自己动手改，偶尔看看版本差异。
5. 导出交给设计和研发。

由此得出三条判断：

- **每个时刻用户只在做一件事。** 讨论时看对话，决定时看待办，写文档时看正文。界面应该让当前这件事占满注意力，其余的收起来。
- **用户真正要处理的东西是"待你决定"。** 需求基线有十几个分组、几十条内容，但需要用户动手的只有少数几条：AI 推断、AI 建议、假设、AI 发现。把这几条单独拿出来，基线本身就可以安静地放在后面。
- **正文是 PRD 编辑器的全部。** 目录、审查意见、版本、来源都是为读写正文服务的，应该在需要时出现，看完就收起。

## 2. 设计理念

**安静的纸面，清楚的下一步。**

- **默认只显示一件事。** 每个页面有一个主区域；辅助内容放在可开关的侧栏、折叠区或菜单里。
- **只有"需要你"的东西有颜色。** 全局只有一个强调色（朱红），它只出现在三种地方：待你处理的计数、需要决定的条目标记、当前位置。确认过的内容没有任何标记，就是普通文字。
- **用排版建立层级，而不是用框。** 层级靠字号、字重、灰度和留白；分隔靠一条细线或一点背景色差。整个产品只有两种"浮起来"的面：输入区和本轮问题。
- **把流程讲成人话。** 按钮写"确认 / 修改 / 不对""稍后 / 忽略"，提示写"记录了 6 项"，不出现内部状态名和 ID（ID 只在来源面板里出现）。

## 3. 视觉风格

| 方面 | 选择 | 理由 |
|---|---|---|
| 底色 | 暖白 `#F6F5F1`，内容面 `#FDFCFA` | 比纯白刺激小，长时间阅读不累；两级就够 |
| 文字 | `#1D1E20` / `#5D6063` / `#8C8F91` | 不用纯黑，减少眩光；三级灰度承担大部分层级 |
| 线 | `#E3E1DB` 一种细线，`#CFCCC4` 用于表头和控件 | 线越少越好 |
| 强调 | 朱红 `#C8553D`，文字用 `#A8432E` | 和暖白底协调；只表示"需要你"和"当前" |
| 字体 | 系统字体（苹方 / 微软雅黑 / Inter）；编号用等宽字体 | 不加载网络字体；等宽编号是唯一的"技术感"来源 |
| 圆角 | 6px（控件）、10px（输入区、本轮问题、菜单） | 小圆角更柔和，但不做卡片感 |
| 阴影 | 只用在浮层（菜单、覆盖式面板、Toast）和两个输入面 | 让"可以操作的地方"自然浮起 |
| 图形 | 项目小图标（32px 平面几何）、标题后一个朱红小方块、空状态的一个黑色三角 | 平面几何只做点缀，不进入信息区域 |
| 正文 | 16.5px，行高 1.8，宽度 700px 左右（约 42 个汉字） | 舒适阅读的中文行长 |
| 动效 | 160–240ms 淡入、侧栏滑入、新写入条目一条下划线 | 只说明"发生了什么"，不表演 |

与 v3 的主要区别：v3 是黑白编辑风格，大标题、粗黑线、编号块、几何刊头、处处可见的状态符号，信息密度高，视觉表达强。v4 把这些全部降到最低，只保留朱红点缀、等宽编号和少量平面图形。v3 的问题是每个区域都在表达设计感，彼此争夺注意力。

## 4. 信息架构

```
项目列表（首页）
└─ 项目
   ├─ 需求   对话 + 待你决定 / 全部需求
   └─ 文档   Brief → PRD 正文 + 目录 / 审查意见 / 来源 / 版本
```

**每个项目只有两个空间："需求"和"文档"。** 定义文档里的阶段（探索、方案、Brief、PRD、审查、交付）是一条进度，不是六个页面：

- 需求探索、产品方案、AI 发现都发生在"需求"空间里。方案分析就是对话中的一轮，产品机会和风险是 AI 发现的一种。
- Brief、PRD、审查、版本、交付都围绕同一份文档，属于"文档"空间。审查意见是文档的批注，版本是文档的历史，导出是文档的一个按钮。

这样顶栏只有两个入口，用户不需要理解六个阶段的划分；进度以一条细的五段条显示在项目列表里。

**计数只在"不在这里"时显示。** 在需求空间时，顶栏的"需求"不显示数字，数字显示在当前页的"需求"按钮上；切到文档后，顶栏"需求"才显示待决定数。同一个数字不会在一屏里出现两次。

## 5. 页面设计

### 5.1 项目列表

一栏，居中，宽 760px。从上到下只有三样东西：

1. **一句话标题和输入框。** "从一个想法开始"，下方一个大输入框，三种开始方式是输入框底部的小标签，不是三张卡片。写了内容"开始"才可用。
2. **继续上次的工作。** 最近的项目单独放大：名称、一句摘要、进度条、**下一步要做什么**（"3 个问题等你回答，8 项内容等你决定"）。点整块进入。
3. **其他项目。** 普通列表行：小图标、名称、下一步、阶段、时间。已交付的折叠在"已交付 N"下。项目多时用右上角的搜索。

没有统计数字、没有活动流、没有仪表盘。用户打开首页只需要回答一个问题："接下来做什么？"

### 5.2 需求探索（核心页面）

左边是对话，右边是"需求"面板（≥1024px 并排，更窄时覆盖在上方，默认收起）。

**对话**
- 不用气泡。左侧一列写"你 / AI"，右侧是文字，读起来像一份讨论纪要。用户的话用灰色，AI 的话用正文色，因为用户已经知道自己说了什么。
- 每次回答下面有一行小字"—— 记录了 6 项，更新了 1 项"。鼠标移上去，右侧对应的需求高亮；点一下切到全部需求并滚动过去。这是对话和需求之间唯一的连接，足够说明"你说的话变成了什么"，又不占地方。
- AI 发现以一行批注的形式出现在提出它的那条消息下面（左侧细线，冲突和风险用朱红线）。点开看依据和建议，可以直接采纳。
- 进入页面时直接停在本轮问题，不需要往下翻。

**本轮问题**
- 页面上唯一的浮起面。一次只展开一个问题：问题加大加粗，下面一句"为什么问"，然后是回答框。已回答的问题收成一行，带"已回答"。
- 每题可以"暂时不确定""跳过"，会记成待确认事项；可以"改为回答"撤销。
- "发送回答"在至少处理一题后可用。旁边一句"回答会整理成需求，由你确认后生效"说明了 AI 不会替用户做决定。

**需求面板**
- 两个视图：**待你决定**（默认）和**全部需求**。
- 待你决定只有两组：AI 发现（采纳 / 稍后 / 忽略）和需要确认的条目。每条显示它属于哪个分组、内容、为什么这样推断，以及"确认 / 修改 / 不对"。全部处理完显示"没有需要你决定的事项"。
- 全部需求按 12 个分组列出，确认过的条目就是一行普通文字，悬停才出现"编辑"和"来源"。核心分组还没有确认内容时，分组名旁边显示"待补充"。
- 面板可以关掉，对话区自动居中变宽。

### 5.3 PRD 编辑器

默认只有正文和一条很轻的工具栏。

- **工具栏**：左边是目录开关和版本（"v3 你 · 今天 14:20 ▾"）；中间在有修改时显示"你修改了 1 个章节"；右边是"导出"和"审查意见 3"。
- **正文**：700px 宽，16.5px，行高 1.8。章节号用等宽灰色小字放在标题前，表格只有横线，列表用小方块，引用用一条朱红线。事实标签（用户输入、假设、待确认）是浅色小标签，待确认用浅朱红。
- **审查意见在正文里是一道荧光笔痕**，必须修改的颜色更深，可选的几乎看不见。点击后右侧打开对应意见并展开。处理完的意见，痕迹自动消失，正文恢复干净。
- **编辑**：鼠标移到章节上，标题右侧出现"来源"和"编辑"。编辑是在原位把这一节换成 Markdown 源码框，⌘↵ 保存，Esc 取消。保存后标题旁出现"你修改"，该节的待处理意见标为"需重新确认"，底部 Toast 说明"这次修改可能影响第 7 节「验收标准」"，并提供"检查这些章节"。
- **审查意见面板**：按严重程度排序，每条一行（严重度、评审方、章节、标题），点开看原文、问题、建议，可以采纳、修改后采纳（写一句自己的意见）、稍后、忽略。有采纳的意见时，底部出现"按采纳的意见修改"，说明 AI 只按这些修改、并先给你看改动。处理过的收在"已处理 N"里。
- **版本**：点版本号打开菜单，列出每个版本的说明、作者和时间，以及"与 v2 对比"。历史版本只读，顶部一条提示可返回。对比时只显示有改动的章节，新增浅绿底、删除浅朱红底加删除线，每行右侧写改动原因。
- **来源**：每节"来源"打开右侧面板，列出这节依据的需求，以及改了之后需要检查的章节。
- 目录和右侧面板在宽屏（≥1200px）默认打开，窄屏默认关闭，打开时覆盖在正文上方。

## 6. 关键设计决策

| 决策 | 理由 | 放弃的做法 |
|---|---|---|
| 项目只有"需求"和"文档"两个空间 | 六个阶段对用户是进度，不是导航；合并后顶栏只有两个入口 | 六个阶段标签页（v3） |
| "待你决定"作为需求面板默认视图 | 用户真正需要做的事一眼可见；完整基线不再是一面墙 | 默认展示 12 个分组全部内容 |
| 已确认内容不加任何标记 | 标记只用来表示"还没定"，信号才有意义 | 每条都有状态图标（v3） |
| 对话不用气泡，用"你 / AI"一列 | 更像讨论纪要，适合长文本；比聊天软件更专业 | 左右气泡 |
| 用一行"记录了 N 项"连接对话和需求 | 解释清楚因果，又不打断阅读 | 每条回答下方一排 ID 标签加连接线（v3） |
| 本轮问题一次只展开一题 | 降低压力，回答更专注 | 三个问题同时展开三个输入框 |
| 审查意见用荧光笔痕标在正文中 | 意见和原文在同一处，正文仍然可读 | 正文旁边的批注卡片 |
| 首页没有统计和活动流 | 首页只回答"接下来做什么" | 刊头、统计数字、活动记录（v3） |
| 计数只在"不在这里"时显示 | 避免同一个数字在一屏出现两次 | 处处显示计数 |
| 文案用口语动词 | "不对"比"拒绝"更像搭档之间的交流 | 状态机术语 |

## 7. 自我审查

在 1440 / 1280 / 1024 / 390 四个宽度检查后做的调整：

| 发现的问题 | 调整 |
|---|---|
| 需求页同一个待决定数字同时出现在顶栏、页面按钮和面板标签上 | 当前空间的顶栏不显示数字；面板打开时按钮不显示数字 |
| 最新一条 AI 消息下的发现默认展开，与右侧面板内容完全重复 | 对话中的发现默认收起，只在面板里展开处理 |
| 进入需求页停在对话开头，要往下翻才看到本轮问题 | 进入时直接定位到本轮问题 |
| 最后一题的按钮仍叫"下一题" | 改为"完成" |
| 手机上本轮问题出现后，"需求"按钮被滚出屏幕 | 窄屏下页面标题行吸顶，"需求"按钮始终可见 |
| 保存后的提示"可能影响 7 验收标准"读起来不通 | 改为"第 7 节「验收标准」" |
| 分组名"已确认决策"里会出现等待确认的决策 | 改为"产品决策" |
| 首页项目的待决定数和需求页不一致 | 首页文案随需求页处理结果实时变化 |

仍然存在、留给正式开发的：

- "待你决定"每条都有三个按钮，条目多时略显重复。正式产品可以考虑"全部确认"或键盘快捷键。
- 对话变长后需要"之前的讨论"折叠，原型只有 6 条消息，没有做。
- 键盘全流程和读屏器测试没有做。

## 8. 原型范围

已实现：上面描述的三个页面和全部交互，四个宽度的响应式布局。数据都是前端 Mock，刷新重置；发送回答后的整理结果和下一轮问题是预设内容；"整理成 Brief""按采纳的意见修改""检查这些章节"在原型中不执行。

没有做的页面：Brief 编辑与确认、问题审查总览、版本记录列表。在本方案里它们都不是独立页面（Brief 是文档的第一个状态，审查和版本是文档的面板和菜单），但 Brief 的确认流程需要在下一阶段补原型。
