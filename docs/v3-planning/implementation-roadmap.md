# V3.0 分阶段开发计划

原则：先定产品和视觉，再动代码；每一批交付都能实际使用；旧运行始终可读。对应定义第 14 章的 Phase 1–6。

| 阶段 | 目标 | 主要交付 | 退出条件 |
|---|---|---|---|
| **0 本阶段（已完成）** | 差距分析与视觉方向 | `docs/v3-planning/` 7 份文档；`design-preview/v3/` 三页原型与截图 | 用户确认视觉方向和 MVP 范围；处理 [open-decisions.md](open-decisions.md) 中标为"开发前"的决策 |
| **1 产品方案细化** | 补齐剩余页面和规则 | 产品方案页、Product Brief 页、问题审查总览、版本记录页的原型；Explorer 提问规则与终止建议规则；Brief 模板；Finding 匹配与状态规则；入口 C 的章节切分规则 | 7 个核心页面（定义 9.10）都有可交互原型并通过四个宽度检查 |
| **2 设计系统落地** | 把原型样式变成正式前端的基础 | 设计 token 与组件（按钮、分段、输入、列表行、状态符号、标记、Toast、空状态）；字体打包；可访问性检查 | 组件在正式前端中可用，有组件测试 |
| **3 数据层与项目** | 项目与基线可以持久化 | 新表与 `project_store`；Project / Item / Revision / Link API；旧运行只读入口；数据库备份脚本 | 创建、恢复、改名、删除项目；条目编辑与确认有记录；旧运行仍可打开；相关测试通过 |
| **4 需求探索** | 端到端的多轮探索 | Explorer Prompt 与 Provider 方法（含 Mock）；Turn API 与 Job / SSE；探索页接入真实数据；Analyst 与探索发现 | 用一个合成需求完成 5 轮以上探索；AI 抽取不会以 confirmed 写入；跳过和不知道生成待确认事项；需要一次经批准的真实模型冒烟 |
| **5 Brief、大纲、逐章生成** | 从基线得到 PRD | Brief 快照与确认；大纲生成与编辑；逐章流式生成、单章重试；章节 ↔ 条目关联 | 由确认的 Brief 生成完整 PRD；中途失败只重做失败章节 |
| **6 编辑、审查、Finding、优化** | 用户驱动的修改闭环 | 章节编辑、乐观锁、版本与对比；项目级 Finding 表与处理 API；三方评审接入章节；Optimizer 提案与确认 | 只修改采纳的问题；人工章节不被覆盖；被拒绝的问题不重复出现 |
| **7 影响分析与质量** | 修改后的关联检查 | 确定性影响范围与 Stale；按需语义检查；四个质量视角；Markdown 导出 | 定义 3.11 的修改类型表逐项有测试；格式修改不触发检查 |
| **8 验证** | 证明比通用大模型有用 | 对照实验方案（定义 11.3）；基线指标采集；用户测试 | 有真实用户数据的对照结论 |

## 依赖关系

```
1 产品细化 ─┬─▶ 2 设计系统 ─────────────┐
            └─▶ 3 数据层 ─▶ 4 探索 ─▶ 5 生成 ─▶ 6 编辑审查 ─▶ 7 影响质量 ─▶ 8 验证
```

2 与 3 可以并行。4 之后每一步都依赖前一步的数据对象。

## 每批交付的检查项

1. 后端：`pytest`、`ruff format --check`、`ruff check`、`mypy`。
2. 前端：`npm run lint`、`npm run typecheck`、`npm run test:run`、`npm run test:e2e`（Mock）。
3. 视觉：1440 / 1280 / 1024 / 390 截图，对照 [design-system.md](design-system.md)。
4. 文档：更新 `docs/product-audit/architecture-map.md`，在 `solution-log.md` 追加记录。
5. 真实模型调用：每个阶段最多一次冒烟，事先获得费用与配置批准。

## 不在计划内

- 不在 V3.0 早期删除旧 `/api/runs` 和自动循环代码；等 Phase 6 完成、确认无人依赖后，再单独决定移除。
- 不做一次性"大重写"：每个阶段结束时主分支都可运行。

## 实施状态（2026-11-08）

阶段 2–7 的 MVP P0 已在正式代码中实现并通过 Mock 测试，记录见 [solution-log.md](../product-audit/solution-log.md) SL-008。未完成：阶段 4–6 要求的真实模型冒烟（需批准）、阶段 8 验证、旧运行转为项目。
