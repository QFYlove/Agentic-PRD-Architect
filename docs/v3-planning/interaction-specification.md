# V3.0 核心页面交互说明

覆盖页面 01 项目工作台、02 需求探索、03 PRD 编辑器。每节分"布局 / 交互 / 状态 / 原型实现情况"。可运行原型见 `design-preview/v3/`，运行方式见 [design-preview/v3/README.md](../../design-preview/v3/README.md)。

## 0. 全局框架

- **顶栏**（56px，吸顶）：Logo、上下文（工作台显示项目数；项目内显示项目编号与名称）、阶段导航、保存状态、用户。
- **阶段导航**：`01 需求探索 · 02 产品方案 · 03 Product Brief · 04 PRD · 05 审查 · 06 交付`。当前阶段下方 3px 朱红线。阶段之间可以自由跳转（定义 2.4），不设锁。<1024px 时移到屏幕底部固定栏。
- **原型条**（28px 黑条）：只在原型中出现，用于在三个页面间切换，并提示 Mock 数据。正式产品没有这一条。
- **保存状态**：编辑后显示"保存中 / 已保存 HH:MM / 保存失败，重试"。原型只显示静态"已保存 14:32"。

## 1. 页面 01 · 项目工作台

### 布局

| 区域 | 内容 |
|---|---|
| 刊头 | 页码与日期、标语、一句定位、右侧几何构图（纯装饰） |
| 统计 | 进行中项目、待处理问题、待确认事项（大号等宽数字，待确认用朱红） |
| A 新建项目 | 三种入口（A 从想法 / B 从已有需求 / C 审查已有 PRD）+ 输入框 + "开始探索 / 开始审查" |
| B 最近项目 | 编辑式索引表：封面图形、编号、名称、摘要、阶段与进度条、问题数、待确认数、修改时间；筛选全部 / 进行中 / 已交付 |
| C 最近修改 | 时间、操作者（你 / AI）、项目、动作、引用对象 ID |

### 交互

1. 选择入口方式后，输入框占位文字随之改变；入口 C 的按钮文字变为"开始审查"。
2. 提交后创建项目，进入需求探索（A / B）或审查（C）。提示语"AI 先追问，不会直接生成 PRD"说明下一步。
3. 点击项目行展开详情（版本、更新时间、待处理说明、"继续 {阶段}"按钮），再次点击收起。只展开一行。
4. "继续"直接跳到该项目当前阶段的页面。
5. 活动记录中的引用 ID 在正式产品中可点击，跳转到对应条目或章节。

### 状态

- 没有项目：列表区显示空状态"这里还没有项目"，新建区保持可用（原型中筛选到无结果时可见）。
- 加载中：列表行用细线骨架，不用转圈。
- 删除项目：行内"更多 → 删除"，确认对话框说明数据处理方式（Q-010）。原型未实现。

### 原型实现情况

已实现：入口选择、输入、筛选、行展开、打开 P-0007、活动列表、四个宽度布局。其他项目的"继续"按钮在原型中禁用。未实现：创建项目的真实逻辑、改名、删除、历史运行区。

## 2. 页面 02 · 需求探索

### 布局（≥1280px）

```
┌ 进度栏 ┬──────── 对话 ────────┬──────── 需求基线 ────────┐
│ ROUND  │ 02 需求探索          │ 需求基线  图例  筛选        │
│  03    │ 你 R0  原始想法       │ ┌ AI 发现（A–E）┐          │
│ 01–12  │   → BASELINE +FR-01…│ └──────────────┘          │
│ 分组   │ AI R1 理解 + 问题     │ 01 产品定位  P0  0/1        │
│ 进度   │ 你 R1 回答           │   ◩ 条目 … 确认 拒绝 编辑    │
│ P0 2/4 │   → BASELINE +USR-01 │ 02 产品目标  尚未明确        │
│ 发现 4 │ ┏ ROUND 03 本轮问题 ┓ │ 03 目标用户 …              │
│ 生成   │ ┃ 01 问题 / WHY / 输入┃ │ …                          │
│ Brief→ │ ┗ 提交本轮 ┛         │ 12 待确认事项               │
└────────┴─────────────────────┴───────────────────────────┘
```

三栏独立滚动；基线栏是浅色"纸面"，与对话区用 1px 黑线分隔。

### 对话区与基线的关联（核心设计）

两个区域共享一套数据：对话中每条用户回答下方列出它写入基线的条目（`+` 新增、`~` 更新），AI 回合下方列出它提出的发现。

1. **悬停或聚焦**一个引用（例如 `+ USR-01`）：
   - 引用反白；
   - 基线中对应条目朱红底高亮，左侧出现 3px 朱红条；
   - 两者之间绘制一条朱红正交连接线（≥1024px）。
2. **点击**引用：基线栏滚动到该条目。
3. 反向同样成立：悬停基线条目，对话中最近一次写入它的引用高亮并连线。
4. 问题与发现关联：问题元数据中显示关联的发现（例如 `F-02 逻辑一致性`），悬停时基线中的发现和其关联条目同时高亮。
5. 本轮提交后新写入的条目出现 700ms 朱红下划线动画。

### 本轮问题

- 每轮 1～3 个问题，按 P0 → P2 排序，每个问题有大号序号、ID、优先级、关联发现、问题正文、"WHY"目的说明、回答框。
- 每个问题可选"暂时不知道"或"跳过"，变为删除线并显示"已记为待确认事项"，可撤销。
- 计数 `已处理/总数` 实时更新；至少处理一个问题后"提交本轮"可用。
- 提交后：输入框禁用、顶部朱红扫描线、按钮变"处理中"；完成后本轮问题和回答进入历史，下一轮问题出现。
- 回答写入基线的状态是"AI 建议"，需要用户确认（提示语说明）。

### 需求基线

- 12 个分组，每组：编号、中文名、英文副标题、优先级、`已确认/总数`、折叠按钮。空的 P0 分组显示"尚未明确 · AI 会优先追问"。
- 条目：状态符号、内容、ID、状态、来源（用户 / AI · 轮次）、修改次数（可展开查看旧值）、关联发现标记。
- 操作：待确认类（推断、建议、假设）常显"确认 / 拒绝 / 编辑"；已确认条目悬停显示"编辑"。编辑为行内文本框，⌘↵ 保存、Esc 取消；保存后状态变为已确认、来源变为用户、旧值进入修改记录。
- 拒绝的条目默认隐藏，底部"显示 N 条已拒绝的推断"可恢复。
- 筛选：全部 / 待你确认（带朱红计数）/ 已确认 / 待确认事项。
- AI 发现：可折叠的列表，每条展开显示依据、影响、建议、类型与关联 ID，操作"采纳 / 暂缓 / 拒绝"，处理后可撤销。

### 进度栏

- 当前轮次大号数字；12 个分组的进度（已确认为黑、部分为灰、未涉及为浅灰）；P0 信息完成度；待处理发现数。
- "生成 Brief →"：任何时候都可以点（定义 2.4 不强迫流程）。正式产品中，若 P0 信息未确认，弹出说明"以下信息尚未确认，会作为待确认事项进入 Brief"，由用户决定是否继续。

### 状态

| 状态 | 表现 |
|---|---|
| 处理中 | 扫描线、输入禁用，已有内容保持可读 |
| 失败 | 本轮回答保留在输入框；显示失败原因与"重试本轮"（沿用 V2.0 失败面板的信息结构） |
| 首轮 | 只有用户原始输入和 AI 首轮问题；基线大部分分组为空 |
| 移动端 | "对话 / 需求基线"两个标签切换；连接线不显示，点击引用切换到基线标签并滚动到条目（原型中只做了切换） |

### 原型实现情况

已实现：历史回合、引用 ↔ 条目高亮与连接线、本轮回答 / 跳过 / 不知道 / 撤销、提交并进入下一轮（使用预设的下一轮内容）、条目确认 / 拒绝 / 恢复 / 编辑 / 修改记录、分组折叠、状态筛选、发现展开与处理、进度栏、移动端标签切换。未实现：真实抽取（提交后写入的条目是按规则生成的 Mock）、失败状态、移动端点击引用跳转。

## 3. 页面 03 · PRD 编辑器

### 布局（≥1440px）

| 区域 | 内容 |
|---|---|
| 工具栏（吸顶） | 页码块、标题、版本切换（v3 人工编辑 / v2 AI 定向优化 / v1 AI 生成）、正文 / 对比 v2、修改状态、检查影响、导出 .md、问题面板开关（带未处理数） |
| 左栏 目录 | 章节编号与标题（两级）、人工修改标记 ✎、每章未处理问题数、当前章节朱红竖条；底部章节数与人工修改数 |
| 中栏 正文 | 文档头（编号、标题、基于哪个 Brief、版本来源、未解决数）；章节：左侧装订线编号、标题、来源标记、问题数、编辑按钮、正文 |
| 右栏 面板 | 标签"审查问题 / 需求追溯"；可收起 |

### 正文阅读

- 正文 16px、行高 1.75、宽度上限 760px。
- 有序列表用两位等宽序号；无序列表用 6px 黑方块；引用用左侧 4px 朱红线 + 纸色底；表格只有横线，表头用等宽小字。
- 事实标签 `[用户输入] [假设] [待确认]` 渲染为小框标记。
- Finding 锚点：被评审引用的原文加下划线，右上角显示 ID；点击后右栏切到该 Finding 并展开，目录与正文定位到所在章节。
- 滚动时根据视口位置自动更新当前章节（目录高亮、追溯面板内容）。

### 编辑

1. 悬停或选中章节时出现"编辑"。点击后正文变为 Markdown 源码编辑框（左侧朱红竖线），底部提示"保存后标记为人工编辑，AI 不会覆盖"。
2. 保存章节：
   - 章节来源变为"人工编辑 · 未检查"，目录出现 ✎；
   - 该章节的待处理 Finding 变为"需重新验证"；
   - 工具栏显示"N 个章节已人工修改 · 待影响检查"，"检查影响"按钮可用；
   - 提示条列出可能受影响的下游章节（例如"修改可能影响 §7 验收标准"）。
3. 内容没有变化时保存不产生修改标记。
4. 历史版本只读：切到 v1 / v2 时显示横幅"正在查看历史版本，只读 · 返回当前草稿"，编辑按钮隐藏。

正式产品还需要：新增 / 删除 / 拖动章节、修改优先级、表格单元格编辑、自动保存与冲突提示。原型未实现这些。

### 版本对比

- "对比 v2"只显示有改动的章节。
- 每行左侧符号列 `+` / `−` / 空，新增行左侧黑色竖条并加粗，删除行朱红竖条、浅朱红底、删除线。
- 每条改动右侧显示修改原因（"采纳 FD-06：版权风险""人工修改"等），关联到 Finding。
- 颜色之外还有符号、竖条、删除线三种区分方式。

### 审查问题面板

- 筛选：全部 / TECH / UX / BIZ；"仅当前章节"。
- 每条记录：左侧严重度竖条、ID、评审角色、章节、处理状态、标题；点击展开原文证据（引用块）、问题说明、"FIX"修改建议，以及操作"采纳 / 修改后采纳 / 暂缓 / 拒绝"。
- 已解决和已拒绝的排在最后，标题加删除线；采纳后提示"已加入下一轮定向优化。只有采纳的问题会被修改"。
- 范围内没有问题时显示"这个范围内没有问题。评审允许零问题。"

### 需求追溯面板

- 当前章节的需求来源（基线条目 ID）。
- 追溯链：用户问题 → 决策 → 场景 → 功能 → 业务规则 → 验收标准（竖线 + 方块节点）。
- 修改后需检查的下游章节。

### 响应式

- 1280–1439：目录与面板变窄，版本只显示编号。
- 1024–1279：目录变为抽屉。
- <1024：单栏；问题面板为覆盖层，默认收起，工具栏"问题 N"打开。
- <600：隐藏"对比"和"检查影响"按钮（移动端以阅读为主），章节编号移到标题上方。

### 原型实现情况

已实现：目录跳转与滚动联动、章节编辑与保存、人工标记与 Stale、影响提示、版本切换与只读、对比视图、Finding 锚点定位、面板筛选与处理、需求追溯、Markdown 导出（真实下载，去掉锚点语法）、面板收起、四个宽度布局。未实现："检查影响"的执行、定向优化提案、章节增删排序、自动保存。

## 4. 原型与正式产品的差异

| 项目 | 原型 | 正式产品 |
|---|---|---|
| 数据 | 前端内存中的 Mock，刷新后重置 | 后端持久化 |
| AI 调用 | 无；提交一轮后 900ms 显示预设内容 | Job + SSE |
| 路由 | `#/workspace`、`#/explore`、`#/editor` | 项目级路由 |
| 字体 | 系统字体 | 待定（D-03） |
| 其他页面 | 产品方案、Brief、审查总览、版本列表在阶段导航中为灰色不可点 | 需在 Phase 2 补充原型 |
