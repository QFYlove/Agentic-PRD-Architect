# Agentic PRD Architect 实施计划

> 依据：memory-bank/design-document.md、memory-bank/tech-stack.md  
> 目标读者：负责逐步实现本项目的 AI 开发者  
> 执行原则：小步实现、测试先行、逐级验收、禁止跨阶段堆叠改动

除非特别说明，本文档中的文件路径均以仓库根目录为基准。

## 1. 执行规则

1. 严格按照 P0、P1、P2、P3 的顺序执行；同一优先级内按照编号执行。
2. 每一步只完成该步骤明确列出的目标，不顺手实现后续功能。
3. 每一步都必须新增或更新相应测试，并实际执行验证。
4. 当前步骤未达到通过标准时，不得进入下一步。
5. 优先使用 Mock LLM 完成开发和自动测试，真实模型只在 P3 接入。
6. 保持 Tech、UX、Business 三个 Reviewer 独立，评分只能由后端确定性聚合。
7. 不引入数据库、Redis、WebSocket、外部任务队列或全局前端状态框架。
8. 不展示模型隐藏思维链，不允许前端渲染模型输出中的原始 HTML。
9. 每完成一个优先级，运行该阶段所有测试、静态检查和构建检查。
10. 每完成一步立即在 memory-bank/progress.md 记录状态和验证结果；只有出现新的架构决策或既有决策变化时才更新 memory-bank/architecture.md。

## 2. 优先级定义

- **P0：工程基础与数据契约。** 后续所有功能的阻塞项。
- **P1：后端 Agent Loop 与实时协议。** 形成可通过 API 完整运行的核心系统。
- **P2：前端交互与可视化。** 形成可操作、可观察的完整 Showcase。
- **P3：真实模型、端到端验收与交付加固。** 达到最终交付标准。

## 3. P0：工程基础与数据契约

### P0-01 固定运行时和包管理策略

**实施指令：** 明确项目使用的 Python 3.11 以上具体小版本、与 Astro 4 兼容的受支持 Node.js LTS 版本，以及 npm 包管理器。添加对应版本声明文件，并确认仓库只保留一种前端 lockfile。

**验证测试：** 在全新终端中读取版本声明，分别检查 Python、Node.js 和 npm 实际版本。

**通过标准：** 三个工具版本符合声明，且仓库不存在相互冲突的包管理 lockfile。

### P0-02 初始化前端工程

**实施指令：** 创建 Astro 4、React 18、TypeScript、Tailwind 和 Node SSR Adapter 的最小工程，保留 src、public 和配置文件的标准目录。

**验证测试：** 安装前端依赖，启动开发服务器，访问首页，并执行一次生产构建。

**通过标准：** 首页可访问，开发控制台无错误，生产构建成功。

### P0-03 建立前端质量工具

**实施指令：** 配置 TypeScript strict、ESLint、Prettier 和 Vitest，加入统一的 lint、typecheck、test 和 build 脚本，并创建一个能够真实运行的最小前端 Smoke Test。

**验证测试：** 分别执行格式检查、Lint、类型检查、最小 Smoke Test 和生产构建。

**通过标准：** 所有检查成功，Vitest 至少发现并通过一个测试，且 TypeScript 严格模式确实启用。

### P0-04 初始化后端工程

**实施指令：** 创建 backend 包、测试目录、运行依赖清单和开发依赖清单，安装 FastAPI、Uvicorn、LangGraph、Pydantic、配置组件、用于兼容协议的 OpenAI SDK 和 SSE 组件。

**验证测试：** 在全新虚拟环境安装两份依赖清单，并导入所有直接依赖。

**通过标准：** 安装过程无依赖冲突，所有直接依赖可以成功导入。

### P0-05 建立后端质量工具

**实施指令：** 配置 pytest、异步测试支持、HTTPX、Ruff 和 mypy，统一 Python 四空格缩进、类型注解和异步 I/O 规则，并创建一个能够真实运行的最小异步 Smoke Test。

**验证测试：** 执行后端格式检查、Lint、类型检查和最小异步 Smoke Test。

**通过标准：** 所有检查成功，pytest 至少发现并通过一个异步测试。

### P0-06 实现并验证配置模型

**实施指令：** 建立后端配置模块，覆盖应用地址、CORS、Mock 开关、模型配置、模型输入和输出价格、阈值、轮次、并发数、TTL、事件缓冲、Heartbeat 和节点超时。缺少当前模型价格时将费用标记为不可用，不得按零费用处理。提供不含密钥的环境变量示例文件。

**验证测试：** 测试默认配置、合法环境变量覆盖、非法数值、Mock 关闭但缺少模型配置、已知和未知模型价格，以及敏感字段不出现在公开表示中。

**通过标准：** 合法配置可加载，非法配置在启动前失败，未知价格不会被显示为零，密钥不会被输出。

### P0-07 定义基础状态枚举和请求模型

**实施指令：** 定义 Run 状态、Node 状态、创建任务请求、恢复任务请求和统一错误响应模型，落实长度、阈值和最大轮次边界。

**验证测试：** 覆盖每个合法状态、过短和过长输入、越界阈值、越界轮次以及未知字段处理。

**通过标准：** 所有合法输入通过，所有非法输入产生明确校验错误。

### P0-08 定义 Reviewer 与聚合结果模型

**实施指令：** 定义单角色评审、三角色聚合结果和反馈集合模型。将总分定义为浮点数，并规定由后端等权计算。

**验证测试：** 验证角色限制、零分和满分边界、非法分数、空反馈，以及三项分数聚合和一位小数舍入。

**通过标准：** 模型拒绝非法数据，指定分数组合得到预期总分。

### P0-09 定义修订计划、PRD 版本和遥测模型

**实施指令：** 定义修订项、修订计划、PRD 版本、Token Usage、运行错误和时间字段，确保集合字段使用独立默认值。

**验证测试：** 创建多个实例并修改其中一个实例的集合，检查其他实例不受影响；同时验证优先级、来源角色和版本号边界。

**通过标准：** 不存在可变默认值共享，所有枚举和数值边界生效。

### P0-10 定义完整任务状态与合法迁移

**实施指令：** 组合完整 Run 状态模型，定义允许的状态迁移和终态规则，区分质量达标、达到最大轮次、取消和失败。

**验证测试：** 覆盖所有正常迁移、非法回退、终态再次迁移、Pause 请求和 Cancel 请求。

**通过标准：** 只有设计文档允许的迁移可以成功，终态不可回到运行态。

### P0-11 建立前后端共享契约

**实施指令：** 以后端 Pydantic 模型和 OpenAPI 为唯一事实来源，保存一组经过后端模型校验的版本化 JSON 契约样本；在前端定义与请求、响应、快照、事件、评审、版本和修订计划一致的 TypeScript 类型。

**验证测试：** 先用后端模型校验契约样本，再用同一批样本执行前端类型和解析测试，覆盖每一种结束状态和事件类型。

**通过标准：** 同一批样本同时通过前后端校验，字段名称、枚举和可空性一致。

### P0-12 初始化 Memory Bank 维护规则

**实施指令：** 在 memory-bank/architecture.md 中记录已经确认的系统边界、核心状态机、REST 加 SSE 协议、单进程限制和不可变架构决策；在 memory-bank/progress.md 中建立 P0 至 P3 的步骤状态清单。以后每完成一步都更新 memory-bank/progress.md，只有架构决策变化时才更新 memory-bank/architecture.md。

**验证测试：** 检查两个文件不再为空，任选一个已完成步骤核对其验证结果、日期和状态，并检查架构文件没有复制大段实施进度。

**通过标准：** memory-bank/architecture.md 能回答“系统如何组成和哪些决定不可随意改变”，memory-bank/progress.md 能回答“当前完成到哪一步以及最近验证结果是什么”。

### P0-13 完成基础阶段门禁

**实施指令：** 清理临时文件，确认目录结构符合设计文档，并补充最小本地环境说明。

**验证测试：** 在干净环境重新安装前后端依赖，执行全部 P0 测试、静态检查和前端构建。

**通过标准：** 所有检查通过，不需要未记录的本地配置，memory-bank/progress.md 已记录 P0 阶段结果。

## 4. P1：后端 Agent Loop 与实时协议

### P1-01 建立 LLM Provider 接口

**实施指令：** 定义文本流式生成和结构化生成两类 Provider 能力，并统一返回内容、Token、模型信息和结束原因。

**验证测试：** 使用最小假 Provider 验证 Generator、Reviewer 和 Optimizer 调用方只依赖接口，不依赖具体 SDK。

**通过标准：** 替换 Provider 实现不需要修改业务工作流。

### P1-02 实现 Mock Generator

**实施指令：** 实现可处理任意合法产品想法的确定性 Mock Generator，并为每个允许轮次提供可区分的版本输出。Podcast 微订阅案例保留为固定 Golden Fixture，默认在 v2 达标；当阈值要求继续迭代时，v3 至 v5 也必须有确定性输出。支持分批异步输出和可关闭延迟。

**验证测试：** 分别使用 Podcast 案例和另一个任意产品想法，在轮次一至五、有延迟和无延迟模式下收集输出，检查分片顺序、最终内容、版本差异和重复运行一致性。

**通过标准：** 所有允许轮次都有合法输出，同一输入和轮次的结果稳定可重复，无延迟模式可快速完成测试。

### P1-03 实现三个独立 Mock Reviewer

**实施指令：** 分别实现 Tech、UX 和 Business Mock 评审，为每个允许轮次提供确定性的分数、摘要和可执行反馈。Podcast 默认场景保持 v1 总分约 71、v2 总分 88；后续轮次必须有定义，分数不得无理由下降。

**验证测试：** 在轮次一至五单独调用每个 Reviewer，检查角色、分数、反馈内容、结构化模型校验、重复运行一致性和预期分数趋势。

**通过标准：** 三个 Reviewer 结果彼此独立，所有允许轮次都有合法结果，v1 和 v2 分数符合演示预期。

### P1-04 实现 Mock Optimizer

**实施指令：** 根据任意未结束轮次的三方反馈生成确定性的修订计划，合并重复项，保留来源角色、目标章节和优先级。

**验证测试：** 在多个轮次输入包含重复、冲突和用户补充要求的反馈集合，检查去重、排序、来源保留和重复运行一致性。

**通过标准：** 所有高优先级反馈进入计划，用户补充要求不会丢失。

### P1-05 建立 Prompt 模板

**实施指令：** 分别建立 Generator、Tech Reviewer、UX Reviewer、Business Reviewer 和 Optimizer 的系统 Prompt，明确数据边界、职责和结构化输出要求。

**验证测试：** 检查每个 Prompt 包含正确角色约束、用户内容边界和禁止输出隐藏思维链的要求，并确认三个 Reviewer 没有复用错误角色描述。

**通过标准：** 五类 Prompt 职责互不混淆，用户输入无法替代系统角色。

### P1-06 实现 Token 与成本聚合

**实施指令：** 建立节点级和任务级遥测累计，按照配置的模型价格估算输入和输出成本，并区分 Mock 标识。当前模型缺少价格配置时，返回“费用不可用”状态，不得回退为零费用。

**验证测试：** 输入多次已知 Token Usage，检查累计值、已知价格计算、舍入、未知价格状态和 Mock 零成本显示。

**通过标准：** 节点和任务累计一致，费用只由后端计算，未知价格不会误导为免费。

### P1-07 实现 InMemoryRunStore 基础操作

**实施指令：** 实现任务创建、读取、原子更新和版本追加，并为每个 Run 使用独立异步锁。

**验证测试：** 覆盖创建、重复创建、未知 Run、并发更新和版本追加顺序。

**通过标准：** 并发更新不丢失，未知任务产生明确错误。

### P1-08 实现 RunStore 容量与 TTL

**实施指令：** 加入最大任务数、完成任务 TTL 和每 60 秒运行一次的周期清理任务，确保运行中和暂停中的任务不会被过期清理。周期清理任务由应用生命周期启动和停止。

**验证测试：** 使用可控时间测试完成任务过期、运行和暂停任务保留、周期清理启动与停止、容量到达上限和清理后重新创建。

**通过标准：** 过期规则和容量规则稳定且可重复测试。

### P1-09 实现 EventStore 事件追加

**实施指令：** 为每个 Run 建立递增事件序号、有界事件缓冲和时间戳，统一生成事件信封。

**验证测试：** 连续和并发追加事件，检查序号严格递增、Run 隔离和缓冲上限。

**通过标准：** 不出现重复或倒序事件 ID，不同 Run 不串流。

### P1-10 实现事件回放

**实施指令：** 支持按 after sequence 和 Last Event ID 回放后续事件，并在请求早于缓冲区时报告事件已过期。

**验证测试：** 覆盖完整回放、部分回放、无新事件、两个恢复参数同时存在和缓冲已淘汰。

**通过标准：** 回放从正确的下一条事件开始，不重复已确认事件。

### P1-11 实现事件订阅和 Heartbeat

**实施指令：** 使用异步通知机制唤醒订阅者，并在空闲期间发送不带业务事件 ID、不写入事件缓冲的 SSE Heartbeat 保活消息；任务终止后允许读取剩余业务事件再结束订阅。

**验证测试：** 测试订阅等待、新事件唤醒、多订阅者、Heartbeat 间隔、长时间空闲后的缓冲内容和终态关闭。

**通过标准：** 无忙轮询，多订阅者收到一致业务事件，Heartbeat 不增加 sequence、不占用缓冲，终态连接正常结束。

### P1-12 实现 RunManager 创建与后台任务

**实施指令：** 让 RunManager 创建 UUID Run、保存初始快照、启动唯一后台任务并维护任务引用。

**验证测试：** 覆盖正常创建、并发创建、同一 Run 重复启动和后台任务完成后的引用清理。

**通过标准：** 每个 Run 只有一个工作流任务，不发生重复执行。

### P1-13 实现状态、事件与快照的原子提交

**实施指令：** 在 RunManager 中建立唯一提交入口；每次状态修改、业务事件追加和 latest event sequence 更新必须在同一个 Run 锁内完成。快照读取使用同一把锁，禁止节点分别直接写 RunStore 和 EventStore。

**验证测试：** 并发执行状态提交、事件订阅和快照读取，反复检查快照状态与 latest event sequence 对应同一次或更早的完整提交，不允许快照跳过尚未反映到状态中的事件。

**通过标准：** 任意快照都能从其 latest event sequence 安全继续订阅，不会丢失状态变化，也不会把未提交状态标记为已消费。

### P1-14 实现应用关闭与后台任务回收

**实施指令：** 在 FastAPI 生命周期关闭阶段停止接收新 Run，停止 TTL 清理任务，唤醒暂停等待和事件订阅，取消所有未结束工作流，并等待任务引用清理。

**验证测试：** 分别在生成中、Reviewer 运行中、PAUSED 和 SSE 订阅等待时触发应用关闭，检查所有后台任务和等待者都在限定时间内结束。

**通过标准：** 关闭过程不悬挂、不遗留后台任务、不产生关闭后的新状态或事件。

### P1-15 实现 Generator 图节点

**实施指令：** 将 Generator 接入 LangGraph，更新活动节点和状态，并为每次生成尝试分配 attempt 标识。将 Provider token 合并为每 50 毫秒或累计 128 个字符时发送的增量事件，以先满足的条件为准；重试前先发送明确的流重置事件。生成完成后保存完整 PRD 版本。

**验证测试：** 使用 Mock Generator 检查节点状态顺序、增量合并频率、attempt 隔离、首次流中途失败后的重置、完整内容校准和 v1 版本保存。

**通过标准：** 正常和重试场景的最终内容都与最后一次 attempt 完整结果一致，不混入失败尝试的旧增量，状态和事件顺序正确。

### P1-16 实现并行 Reviewer 节点

**实施指令：** 将三个 Reviewer 作为独立节点并行运行，让每个分支只写入本角色的独立结果字段，并分别发布开始、完成和失败事件。禁止多个分支覆盖同一状态字段。

**验证测试：** 使用同步屏障或受控 Future 证明三个节点在任一节点完成前都已启动，检查不同完成顺序下三个结果均被保留，并注入并发写入冲突检测。

**通过标准：** 三个 Reviewer 确实并行，结果写入各自字段，任何完成顺序都不会丢失或覆盖其他角色结果。

### P1-17 实现评审聚合节点

**实施指令：** 等待三份合法评审结果，确定性计算总分，合并反馈并发布分数更新事件。

**验证测试：** 覆盖三份合法结果、缺少一个结果、角色重复和非法分数。

**通过标准：** 只有三种角色齐全时才产生聚合结果，总分不由模型提供。

### P1-18 实现质量门和正常完成

**实施指令：** 在聚合后检查质量阈值，达到阈值时进入 COMPLETED，记录完成时间和最终版本。

**验证测试：** 覆盖低于、等于和高于阈值三种边界。

**通过标准：** 等于阈值即完成，完成后不再执行 Optimizer。

### P1-19 实现最大轮次终止

**实施指令：** 在未达标时检查当前轮次，达到上限后进入 MAX_ITERATIONS_REACHED，不将其标记为质量达标。

**验证测试：** 覆盖最大轮次为一、三和五的情况，并检查 Generator 调用总数。

**通过标准：** 调用次数永不超过配置上限，两种成功/未达标终态清晰区分。

### P1-20 实现 Optimizer 和下一版本循环

**实施指令：** 在未达标且仍有轮次时运行 Optimizer，保存修订计划，递增轮次，再调用 Generator 生成下一版本。

**验证测试：** 执行 Mock 两轮流程，检查 v1、修订计划、v2 的顺序和版本号。

**通过标准：** v2 明确吸收修订计划，轮次只在进入下一次 Generator 前增加。

### P1-21 实现安全暂停点

**实施指令：** 让 Pause 请求先进入 PAUSE_REQUESTED，并仅在聚合完成、Optimizer 开始前进入 PAUSED。PAUSED 期间冻结单任务总超时计时，但该 Run 仍计入并发运行上限。

**验证测试：** 分别在 Generator、Reviewer 和质量门期间请求暂停，检查当前节点先安全结束、Optimizer 未启动、暂停等待不消耗总超时、并发计数不释放。

**通过标准：** 暂停不会破坏正在执行的模型调用，PAUSED 只出现在规定安全点，长时间暂停不会触发 Run 超时或释放并发名额。

### P1-22 实现恢复和用户补充要求

**实施指令：** 仅允许 PAUSED Run 恢复，将用户补充优化要求保存并传入 Optimizer，恢复后清理待处理字段。

**验证测试：** 覆盖有补充要求、无补充要求、非暂停状态恢复和重复恢复。

**通过标准：** 合法恢复只执行一次，用户要求出现在修订计划中。

### P1-23 实现取消和晚到结果隔离

**实施指令：** 支持任意非终态请求取消；每个节点在提交结果前必须在同一 Run 锁内重新检查取消状态，阻止取消后返回的 Provider 结果写入版本、评审、遥测或业务事件。

**验证测试：** 在等待、生成和评审期间分别取消，并模拟取消后文本、评审和 Token Usage 晚到。

**通过标准：** 最终状态稳定为 CANCELLED，取消后不新增有效版本、分数、费用或业务事件。

### P1-24 实现结构化输出重试

**实施指令：** 对 Reviewer 和 Optimizer 结果执行 Pydantic 校验。可重试的传输错误最多执行两次原始请求；一旦收到响应但校验失败，只执行一次格式修复，不再重新执行原始请求。认证失败、无效模型名和第二次格式失败立即结束节点。

**验证测试：** 覆盖首次成功、传输错误后第二次成功、首次结构非法后修复成功、修复失败、认证失败和无效模型名，并精确检查调用次数。

**通过标准：** 任一结构化节点最多执行两次原始传输尝试和一次格式修复，失败产生安全且明确的 Run 错误。

### P1-25 实现超时、文本重试和并发限制

**实施指令：** 为各 LLM 节点和整个 Run 设置超时。Generator 的可重试传输错误最多尝试两次，并遵守 P1-15 的 attempt/reset 语义。Run 总超时只累计非暂停时间。QUEUED、所有运行状态、PAUSE_REQUESTED、PAUSED 和 CANCEL_REQUESTED 均计入并发上限；终态不计入。

**验证测试：** 注入节点超时、非暂停时间达到 Run 总超时、长时间暂停、Generator 首次失败后恢复、永久错误、各活动状态下的并发上限和终态释放名额。

**通过标准：** 不存在无限等待或无限重试，暂停时间不触发 Run 超时，所有活动 Run 都占用名额，终态及时释放名额，超限请求明确返回 429。

### P1-26 实现创建、快照和健康 API

**实施指令：** 实现创建 Run、读取完整快照和健康检查接口；创建接口只负责启动任务，不保持长流连接。

**验证测试：** 覆盖成功创建、输入校验、未知 Run、快照最新事件序号和健康响应不泄露密钥。

**通过标准：** 状态码与设计一致，快照足以恢复前端状态。

### P1-27 实现 Pause、Resume 和 Cancel API

**实施指令：** 将三个控制接口连接到 RunManager，统一处理非法状态和幂等取消。

**验证测试：** 对每种 Run 状态执行三个控制操作，检查允许和拒绝矩阵。

**通过标准：** 合法操作成功，非法操作返回冲突错误，重复取消保持稳定。

### P1-28 实现 SSE API

**实施指令：** 使用标准 SSE 响应输出业务事件 ID、事件名和 JSON 数据；恢复起点取 after sequence 与 Last Event ID 中较大的合法值。Heartbeat 使用无 ID、无缓冲的保活消息。支持事件回放、过期报告和终态关闭。

**验证测试：** 使用异步 HTTP 客户端验证响应头、业务事件格式、递增 ID、两个恢复参数的优先规则、Heartbeat 不占序号、断线补发、过期事件和关闭行为。

**通过标准：** 浏览器 EventSource 所需协议完整，断线后不丢失缓冲区内事件。

### P1-29 实现统一错误和 CORS
