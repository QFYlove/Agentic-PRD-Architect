## 当前产品

帮助产品经理从模糊想法出发，经过需求探索、产品分析、Product Brief、逐章生成 PRD、四维审查和定向优化，得到可交付的 PRD。详细流程见 [README](../README.md) 和 [product-definition.md](../docs/product-definition.md)。

V2 的单次运行流程（Generator → 三个 Reviewer → Aggregator → Optimizer 自动循环）作为只读历史保留在 `/runs` 和 `/api/runs`，不再是主流程。

## 已具备的能力

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| 项目 | 完成 | 三种入口（想法 / 已有需求 / 审查已有 PRD）、列表、继续、改名、软删除；不受 V2 TTL 和数量上限影响 |
| 需求探索 | 完成 | 每轮 1～3 问并说明目的；回答 / 跳过 / 暂时不确定；简要 / 详细两档；不重复提问 |
| 需求基线 | 完成 | 12 个分组、6 种状态、来源、优先级、修改记录、关联；AI 不能确认或否定条目，用户原话逐字核对 |
| Product Analyst | 完成 | 缺口 / 冲突 / 场景 / 风险 / 机会，必须引用条目；可检查当前基线或某个 Brief 版本 |
| Product Brief | 完成 | 由代码从基线组装，可编辑，整体确认后冻结；版本保留；正文不含内部编号 |
| 大纲与逐章生成 | 完成 | 动态大纲，可增删、改名、排序；逐章流式生成，单章失败单独重试 |
| PRD 编辑 | 完成 | 按章节编辑 Markdown，乐观锁，人工章节标记，章节来源 |
| 四维审查 | 完成 | Product / UX / Tech / Biz 并行独立；领域外意见丢弃；允许零问题；章节未完成时不能审查全文 |
| Aggregator | 完成 | 跨角色合并、与已有意见匹配保持编号、被拒绝的不重复、复查结论；分数由代码计算，四个分开显示 |
| Finding 管理 | 完成 | Open / Accepted / Modified / Rejected / Deferred / Resolved / Stale，处理记录，按角色 / 严重程度 / 章节筛选 |
| 定向优化 | 完成 | 只用已采纳意见；提案可部分应用；期间被改过的章节跳过不覆盖 |
| 影响分析 | 完成 | 规则判断修改类型；格式修改不触发；相关意见标 Stale，依赖章节标待复查，可只复查这些章节 |
| 版本 | 完成 | 只追加；记录修改人、原因、关联意见；章节级对比；审查前正文有变化时自动保存版本 |
| 质量 | 完成 | 文档质量、需求成熟度、实施就绪度、风险与阻塞四项独立指标，无数据不显示数字 |
| 导出 | 完成 | Markdown，去掉内部标记和系统编号，保留用户自己写的编号 |
| Job 与 SSE | 完成 | 每次模型调用一个 Job；事件持久化、断线续传；重启时未完成任务标 `JOB_INTERRUPTED` |
| 数据迁移 | 完成 | `v3_*` 表、编号迁移（当前到 2）、迁移前自动备份到 `data/backups/`、`rollback_v3` |

## 已知风险

- 跨轮匹配同一意见使用保守的文本重叠规则，换说法的同一问题可能被当成新问题。
- 影响分析依赖章节依赖、共享需求条目和关键词，关系未标出时会漏检。
- 单 Worker、本地 SQLite、同步读写，只适合单用户本地使用。
- 锁定的 Astro 4 / Mermaid 10 依赖存在已知上游告警。

## 下一步

获得批准后，关闭模拟模型，用 DeepSeek 或 GLM 完整跑一遍工作流（约 22～28 次调用），记录 Token、费用和各类校验的降级比例，再据此调整 Prompt。
